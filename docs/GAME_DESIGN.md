# 游戏规则与后续数值调整

## 时间

一局28个日历日。每天显示9～20点，夜晚跳过。正常有效工作8小时。日历第26天（索引25，第四周周五）18点交付，第27天周六18点补交。发薪日为每周日；提前结算时最后一周工资结算一次。

游戏以0.25小时步长推进，1倍速约每2秒一游戏小时。早会、随机事件、验收窗口会暂停；浏览器切入后台暂停并存档，防止后台回来突然失败。

## 人天与资格

初级基础效率1人天/8小时，中级1.3，高级1.65。低精力/健康降低效率，好电脑与专家提高效率。任务需求与岗位、技能、开发最低级别必须匹配。部门工位约束最大并行人数。

每个工位绑定一个需求，不会自动抢其他需求；同一员工只有一项工作或培训。阶段未解锁时，该员工等待。调走员工不损失已完成的人天。工位被占不允许覆盖。

培训默认8个有效工作小时，培训教室升级可减少到6/4小时；暂停保留进度。自动加入失败时保留技能并记录原因。

## 健康、事件与Bug

正常工作消耗精力；加班更快消耗精力并伤健康。正常休息和周末恢复。低健康在每天开始时仅抽一次请假风险。事假提前一天通知；请假期间不工作、不培训，工资仍支付。

开发质量按贡献者级别、健康和精力累计。一个需求的Bug只在开发完成时生成一次。测试会发现严重Bug，普通Bug可能漏检。测试发现后进入修复，开发完成后回归；验收才发现的普通Bug回到修复流程。回归不无限重抽新Bug。修复可换人，非原开发有15%熟悉损耗。

随机事件有频率限制，首两天不出现客户变更。每次事件可暂停决策，需求變更可拒绝。

## 第一版可调范围

在 `game.js` 调整初始现金、工资、每阶段工作量、项目收益、事件概率、加班健康消耗、培训时长与升级价格。扩充需求池时必须确保至少有岗位匹配的招聘/培训路径，避免随机生成无法完成的任务。
